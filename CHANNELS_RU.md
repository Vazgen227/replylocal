# Подключение источников

Общее правило: сначала проверьте стабильный HTTPS-домен, ключ шифрования и worker из `START_HERE_RU.md`. Владелец или администратор добавляет подключение; оператор видит входящие и отвечает, но не получает токены. Для каждого бота/номера/Instagram-аккаунта допускается одно подключение во всём сервисе, чтобы не направить сообщения двум компаниям.

## Сайт

«Интеграции → Чат для сайта»: включите чат, настройте приветствие, общий режим ИИ и дневной лимит. Режим ИИ и лимит применяются также к мессенджерам; переключатель «включить чат» относится к публичному сайту. Добавьте знания компании. Скопируйте код установки в HTML сайта перед закрывающим `</body>`. При CSP сайта разрешите загрузку script и frame с вашего домена ReplyLocal. Можно использовать прямую ссылку на чат без установки скрипта.

Виджет запрашивает имя, необязательный контакт и согласие; авторизация клиента не нужна. В браузере сохраняется непрозрачный токен диалога. Источник — `website`; UTM и адрес страницы показываются в карточке сотрудника. UTM — данные посетителя, не доказательство покупки или личности. Посетитель не видит внутренние заметки и знания целиком.

## Telegram: отдельный бот

1. Создайте своего бота через официальный BotFather и получите bot token.
2. В «Каналах общения» выберите Telegram, дайте понятное имя, вставьте токен и режим «Отдельный бот».
3. «Проверить и сохранить» вызывает `getMe`; затем «Включить приём» устанавливает `setWebhook` с секретным заголовком.
4. С другого аккаунта откройте бота, нажмите Start и задайте вопрос. `/start` тоже является входящим сообщением; без релевантных знаний он может передать разговор сотруднику.
5. Найдите диалог во входящих, возьмите его и ответьте. Убедитесь, что ответ появился в Telegram и в кабинете виден `Принято сервисом`.

Поддерживаются личные чаты; группы и сообщения других ботов игнорируются. Бот не начинает разговор с произвольным пользователем и не читает личный Telegram владельца. Установка нового webhook заменяет предыдущий webhook этого бота: не используйте тот же токен одновременно в другой системе.

## Telegram Business

Это режим официального подключённого бизнес-бота, а не авторизация личного аккаунта по номеру телефона.

1. Включите у бота business mode через BotFather и подключите его к своему бизнес-аккаунту Telegram с правом ответа на нужные личные чаты.
2. Укажите token, режим Business и числовой Telegram user ID **владельца подключённого бизнес-аккаунта**.
3. Включите приём. Для каждого business_message сервис проверяет `getBusinessConnection`: владелец должен совпасть, подключение должно быть включено и иметь право ответа.
4. Напишите бизнес-аккаунту с другого аккаунта и проверьте обратный ответ. Для отправки используется `business_connection_id`, поэтому ответ идёт от подключённого бизнес-аккаунта.

Не подставляйте ID клиента вместо ID владельца. Ошибка прав/владельца попадает в очередь, а сообщение не маршрутизируется в чужую компанию. Свободный ответ после 24 часов блокируется.

Официальная документация: https://core.telegram.org/bots/api ; https://core.telegram.org/api/bots/connected-business-bots

## WhatsApp Business Cloud API

Используется официальный Cloud API. Обычный личный WhatsApp, WhatsApp Web и QR-эмуляция не поддерживаются.

1. В Meta настройте WhatsApp Business Platform, бизнес-аккаунт и номер. Для разработки можно использовать тестовый номер и разрешённых получателей.
2. Получите access token с доступом к нужному номеру и разрешением `whatsapp_business_messaging`; управление подпиской WABA обычно требует `whatsapp_business_management`. Настройте разрешения приложения для выбранного сценария, а для клиентов вне ролей приложения — необходимый доступ/проверку Meta.
3. В ReplyLocal выберите WhatsApp, вставьте **Phone Number ID** (не сам номер телефона и не WABA ID), token и App Secret того приложения, которое подписывает webhook. Если сервер настроен на общее приложение Meta, App Secret можно оставить пустым — используется `META_APP_SECRET`.
4. Сохранение проверяет номер через Graph API. В Meta укажите показанные ReplyLocal callback URL и Verify token. Подпишите поле `messages` и нужный WABA на приложение. Одной успешной проверки URL недостаточно: приложение должно получать события именно этого бизнес-аккаунта.
5. Включите приём в ReplyLocal. Напишите на номер и проверьте входящий диалог, обратный ответ и delivered/read при наличии этих событий.

Отправляются обычные текстовые ответы в 24-часовом окне обслуживания. Отправка шаблонов вне окна не добавлена. Ограничения номера, качество аккаунта и стоимость использования определяет Meta. Постоянный рабочий token предпочтительнее краткоживущего токена из страницы первичного тестирования.

Официальная документация: https://developers.facebook.com/documentation/business-messaging/whatsapp/ ; https://developers.facebook.com/documentation/business-messaging/whatsapp/webhooks/overview

## Instagram

Реализован **Instagram API with Instagram Login** на `graph.instagram.com`. Не смешивайте с токенами Facebook Login / Facebook Page другой схемы API.

1. Нужен профессиональный Instagram Business/Creator и приложение Meta с настройкой Instagram Login.
2. Получите Instagram User access token с `instagram_business_basic` и `instagram_business_manage_messages`; разрешите доступ подключённых инструментов к сообщениям. Для сторонних компаний понадобится соответствующий доступ приложения и проверка Meta.
3. Узнайте `user_id` профессионального аккаунта через `GET /me?fields=user_id,username` и укажите его в ReplyLocal как Instagram User ID. Укажите token и App Secret приложения, либо используйте серверный `META_APP_SECRET`.
4. В настройках Instagram webhook приложения добавьте показанный callback URL / Verify token, события `messages` и при необходимости `messaging_seen`. Подпишите сам профессиональный аккаунт на приложение через его `subscribed_apps` по документации текущей версии Instagram Login. Проверяйте подписку аккаунта отдельно от проверки URL.
5. Включите приём. Отправьте аккаунту личное сообщение от другого допустимого тестового/реального пользователя, затем ответьте из ReplyLocal.

При первичном входящем событии интерфейс может показывать Instagram ID вместо username: без дополнительного запроса профиля нельзя выдумывать имя. Эхо собственных отправок игнорируется. Комментарии под постами, групповые чаты, реклама и публикации не входят в обработку. Свободный ответ ограничен 24 часами.

Документация Meta: https://developers.facebook.com/documentation/instagram-platform/instagram-api-with-instagram-login/messaging-api ; официальная коллекция Meta: https://www.postman.com/meta/instagram/overview

## Одно приложение Meta для нескольких компаний

Задайте серверные `META_APP_SECRET` и `META_VERIFY_TOKEN` (случайный секрет от 32 символов). При подключении с этим App Secret кабинет покажет единый адрес `https://ВАШ-ДОМЕН/api/webhooks/meta` и общий Verify token. Он не меняется при добавлении новой компании.

Сервис проверяет HMAC общей подписи и распределяет события по **Phone Number ID** WhatsApp или `entry.id` Instagram. Затем проверяет сохранённый App Secret подключения и направляет события только владельцу этого account ID. Для каждой компании всё равно нужны её токен, нужные разрешения и подписка её аккаунта на приложение. Незнакомые аккаунты не создают диалоги.

Если компания использует отдельное приложение с другим App Secret, кабинет показывает индивидуальный `/api/webhooks/UUID` и индивидуальный Verify token. Не меняйте глобальный callback одного и того же Meta-приложения на UUID очередного клиента: используйте общий endpoint для общего приложения.

## Viber

Используется официальный Viber Bot API. Произвольная переписка обычного личного Viber по номеру телефона не читается. Создание новых Viber-ботов доступно на коммерческих условиях Rakuten Viber / партнёров; token не выдаётся кодом ReplyLocal.

1. Получите активного Viber-бота и его authentication token.
2. Выберите Viber, введите название и token, сохраните. `get_account_info` проверяет аккаунт.
3. Включите приём: `set_webhook` устанавливает публичный HTTPS URL. Viber должен успешно проверить callback с ответом HTTP 200.
4. Пользователь открывает бота и пишет ему. Затем проверьте входящий диалог и ответ из кабинета. Первое сообщение пользователя делает его подписчиком; произвольная отправка незнакомым номерам не добавлена.
5. `delivered`, `seen`, `failed` обновляют состояние отправки. Большие числовые message_token сохраняются без округления.

Документация: https://developers.viber.com/docs/api/rest-bot-api/

## Если канал не заработал

- Нет «последнего события»: проверьте стабильный домен, доступ без Vercel login, URL webhook, включённый приём, разрешения, account ID и подписку аккаунта.
- Webhook получает 403: неправильный App Secret / подпись / verify token, либо устаревший Telegram webhook после замены токена.
- Во входящих пусто, но событие есть: откройте очередь, проверьте worker и ошибку задачи.
- Текст сохранён, но не отправлен: смотрите «Доставка ответов». `pending` — очередь, `failed` — известная ошибка, `uncertain` — сервис не подтвердил результат. Перед повтором `uncertain` проверьте исходный чат.
- `REPLY_WINDOW_CLOSED`: дождитесь нового сообщения клиента или используйте разрешённый способ в исходном канале. Повтор кнопкой не отменяет ограничения API.
- Смена токенов, блокировка номера, неоплаченный Viber, невыданные разрешения Meta решаются в соответствующем бизнес-аккаунте; зелёная сборка приложения их не проверяет.
