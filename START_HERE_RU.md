# ReplyLocal 0.4 — единый кабинет общения с клиентами

Это полный исходный проект Next.js + PostgreSQL. Интерфейс, API, очередь обработки, интеграции и тесты находятся в одном архиве. Открой сначала этот файл; подробности каналов — в `CHANNELS_RU.md`, проверка перед клиентом — в `ACCEPTANCE_RU.md`.

## Что делает продукт

Клиент пишет на сайт, Telegram-боту / подключённому Telegram Business, в WhatsApp Business, Viber-боту или профессиональному Instagram-аккаунту. Подписанный webhook сохраняется в PostgreSQL. Рабочий процесс создаёт диалог в общих «Входящих», использует знания именно этой компании для ответа ИИ или передаёт разговор сотруднику. Ответ сотрудника возвращается в исходный канал через официальное API. Состояние доставки показывается отдельно от сохранённого текста.

У каждой компании свои сотрудники, знания, диалоги, подключения, расходы и подписка. Есть роли владельца, администратора и оператора, приглашения, переключение компаний, назначение ответственного, внутренние заметки, следующий шаг, результат сделки, поиск истории и CSV-отчёт по источникам. Веб-виджет сохраняет UTM-метки и адрес страницы без query-параметров. ИИ не получает внутренние заметки.

Отчёты считают обращения, созданные в выбранном месяце UTC, и их текущие результаты. Продажу и её сумму отмечает сотрудник. Прибыль до расходов на канал вводится отдельно; неизвестное значение оставляется пустым. Расходы на рекламу / тариф канала вводятся за месяц. Разные валюты не складываются. Это управленческий отчёт по обращениям, а не банковская сверка или автоматическая атрибуция оплат.

## Что уже проверено, а что требует ваших аккаунтов

Автоматические проверки работают на отдельной временной PostgreSQL-совместимой БД и локальных ответах API. Они не используют ваши пароли Neon, настоящие сообщения клиентов и платные запросы. Проверены сценарии четырёх мессенджеров, сайта, команды, отчётов, очереди и Stripe SDK. Результат проверки — в `VERIFICATION.md`.

Реальные бизнес-аккаунты, разрешения Meta, коммерческий Viber-бот, почтовый домен и платёжный аккаунт нельзя выдать внутри ZIP. Их надо подключить по инструкции, затем пройти живой приёмочный сценарий для каждого используемого канала. Архив не означает, что ваши аккаунты уже авторизованы или что Meta одобрила приложение.

## 1. Обновить существующий проект

1. Сделайте резервную копию исходников и базы перед миграцией. Для проверки обновления удобно использовать отдельную БД / ветку Neon.
2. Распакуйте архив в новую папку. В нём нет `node_modules`, `.next`, `.git` и `.env.local`.
3. Сохраните свой `.env.local` отдельно; не публикуйте его в Git. Перенесите значения в новый проект и добавьте новые переменные из `.env.example`. Если файла ещё нет, скопируйте `.env.example` в `.env.local` и заполните.
4. В терминале в папке, где лежит `package.json`, выполните:

```powershell
npm ci
npm run db:migrate
npm run lint
npm run typecheck
npm test
npm run build
```

Миграция `003_omnichannel.sql` добавляет новые таблицы и поля. `001` и `002` сохранены без изменения содержимого. Повторный запуск мигратора безопасен; уже применённые миграции с другим checksum он отклоняет. Не удаляйте таблицы и записи `schema_migrations`, чтобы обойти такую ошибку.

Для переноса в существующий Git-репозиторий используйте исходники этого архива, сохранив свою историю `.git` и локальные секреты. Зафиксируйте изменения отдельным коммитом. В архиве один `src/proxy.ts`; старый `middleware.ts` рядом с ним не нужен.

Запускать приложение на домашнем ПК необязательно: можно развернуть проверочную версию на Vercel. Не подключайте проверочный деплой к работающим webhook реального бизнеса — у Telegram/Viber один активный адрес webhook на бота.

## 2. Переменные сервера

Обязательны:

- `DATABASE_URL` — ваша строка PostgreSQL с проверкой TLS, например `sslmode=verify-full`.
- `APP_URL` — точный HTTPS-адрес публичного приложения, без `/ru` и без пути. Origin должен совпадать с адресом в браузере.
- `CHANNEL_ENCRYPTION_KEY` — случайные 32 байта в base64. Шифрует токены каналов и содержимое писем с одноразовыми ссылками. Сгенерируйте один раз и сохраните в надёжном месте:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

- `CRON_SECRET` — отдельный случайный секрет для фонового обработчика:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Не меняйте ключ шифрования без отдельной процедуры перешифрования: старые токены перестанут читаться. Не используйте ключ из тестов. Не добавляйте секретам префикс `NEXT_PUBLIC_`.

Для ответов ИИ: `OPENAI_API_KEY` и модель Responses API с поддержкой Structured Outputs в `OPENAI_MODEL`. Без ключа обращения принимает оператор. Подписка ChatGPT не оплачивает API автоматически. Ограничения попыток: минимум из лимита компании, серверного лимита тарифа и общего `AI_GLOBAL_DAILY_LIMIT`. Попытка учитывается до вызова провайдера, в том числе при его ошибке.

Для писем: `RESEND_API_KEY` и `EMAIL_FROM` с подтверждённым доменом. Приглашение можно передать ссылкой вручную, если почта не настроена; интерфейс прямо сообщает, что письмо не отправлено. Восстановление пароля без почтового сервиса недоступно. Ссылки приглашений действуют 48 часов, сброса — 30 минут и используются один раз.

`ALLOW_SIGNUP=true` открывает самостоятельную регистрацию компаний. При `false` уже приглашённый сотрудник всё равно может создать аккаунт по своей ссылке. Для ограниченного запуска оставьте публичную регистрацию закрытой.

## 3. Vercel и Neon

В Vercel добавьте переменные в настройки проекта для нужного окружения и сделайте новый deployment. Секреты вводятся в Environment Variables, а не в исходный код. Миграции применяются отдельно командой выше к нужной БД. `npm run build` не выполняет миграции и не меняет схему.

Публичные webhook должны открываться без страницы входа Vercel / защиты Preview. Используйте стабильный домен, совпадающий с `APP_URL`. Проверьте, что Vercel и БД имеют нормальную сетевую связность и что настройка продолжительности Node-функций допускает 60 секунд для маршрутов обработки.

## 4. Обязательно запустить фоновую обработку

Входящее событие сначала сохраняется; `after()` запускает обработку сразу после ответа webhook. Это ускоряет доставку, но не заменяет постоянный обработчик: при перезапуске процесса задачи остаются в БД.

Вариант A: отдельный всегда работающий Node-процесс на вашем сервере / worker-host. Ему достаточно кода из архива, зависимостей, `APP_URL` и `CRON_SECRET`:

```powershell
npm ci
npm run worker
```

Вариант B: планировщик вызывает `POST` или `GET` `https://ВАШ-ДОМЕН/api/jobs/run` с заголовком `Authorization: Bearer ЗНАЧЕНИЕ_CRON_SECRET` не реже раза в минуту. Секрет хранится в настройках планировщика; не в URL. Частоту выбирайте по объёму обращений. Для более быстрой обработки очереди используйте worker-процесс. В архиве не включён планировщик с предположением о вашем тарифе Vercel.

Планировщик с редким, например суточным запуском недостаточен для оперативной поддержки. После настройки откройте «Интеграции → Очередь и ошибки обработки». Ошибки можно повторить; ответы с неопределённым результатом отправки требуют отдельного подтверждения, поскольку повтор может создать дубль.

## 5. Подписки Stripe

Оплата настраивается владельцем сервиса, не каждым бизнесом отдельно:

1. В своём Stripe создайте повторяющуюся цену Starter с вашей суммой, валютой и периодом.
2. Заполните `STRIPE_SECRET_KEY`, `STRIPE_PRICE_STARTER`.
3. Создайте webhook `https://ВАШ-ДОМЕН/api/billing/webhook` для `customer.subscription.created`, `customer.subscription.updated`, `customer.subscription.deleted`; добавьте его signing secret в `STRIPE_WEBHOOK_SECRET`.
4. Включите и настройте Customer Portal в Stripe.
5. Проверьте оплату, управление подпиской и отмену в test mode. Только после этого меняйте все значения на live; test и live не смешиваются.

Владелец компании открывает «Настройки → Подписка», Checkout показывает фактическую сумму до оплаты. Повторное нажатие возвращает существующую незавершённую Checkout-сессию. Статус меняет подписанный webhook; данные подписки дополнительно читаются из Stripe. Старые события не должны восстанавливать отменённую подписку.

`BILLING_ENFORCED=false`: компании без активной подписки имеют пилотный лимит ИИ `AI_PILOT_DAILY_LIMIT` (по умолчанию 50/UTC-день). Starter active/trialing — `AI_STARTER_DAILY_LIMIT` (500). `BILLING_ENFORCED=true`: без active/trialing автоматические ответы выключены; входящие сообщения и работа оператора сохраняются. Не включайте этот режим раньше настройки оплаты. При отсутствии Stripe интерфейс честно показывает ручное обслуживание оплаты.

Согласуйте доступность Stripe для своего юридического лица и выбранную коммерческую модель. Код не создаёт вам платёжный аккаунт.

## 6. Эксплуатация

- Ежедневно проверяйте ошибки очереди и доставки. `sent` означает принятие API, `delivered/read` показываются только при соответствующем событии провайдера. Telegram не предоставляет здесь статусы прочтения.
- Настройте резервное копирование и восстановление PostgreSQL; проверьте восстановление на отдельной БД.
- Планируйте `npm run db:maintenance`. Он удаляет просроченные сессии/ссылки, завершённые задачи старше 7 дней и переписки без активности старше `DATA_RETENTION_DAYS` (90 по умолчанию). Неактивная история и соответствующие итоги могут исчезнуть из аналитики после удаления. Сохраняйте нужные отчёты/экспорты согласно своему сроку хранения.
- При увольнении сотрудника удалите доступ в команде: сессии этой компании отзываются, назначения снимаются. Чужую компанию удалить или переключить без членства нельзя.
- Обновляйте истекающие токены в «Интеграциях»; замена требует повторного включения и, при смене приложения Meta, перенастройки webhook.

## Границы этого выпуска

Текстовые личные обращения и ответы. Вложения отмечаются для человека; скачивание файлов, расшифровка голосовых и отправка медиа из кабинета не добавлены. WhatsApp templates и инициативные рассылки не реализованы; свободный ответ ограничен 24 часами после входящего сообщения для WhatsApp/Instagram/Telegram Business. Telegram/Viber подключаются к ботам, а не читают произвольную личную переписку владельца.

Не подключены CRM/календарь/остатки магазина и API маркетплейсов, поэтому ИИ не обещает свободное время записи или наличие товара, если этих данных нет в знаниях. Нет автоматического объединения личности одного человека между разными каналами и импорта старых переписок. Приложение принимает новые webhook после подключения. Подключение Meta сейчас выполняется токенами в кабинете; OAuth/Embedded Signup для массового самообслуживания — отдельное расширение, а не скрытая возможность этой версии.

Эти ограничения нужно учитывать в обещаниях клиенту. Реальный результат запуска подтверждается приёмкой вашего аккаунта, а не только зелёной сборкой.
