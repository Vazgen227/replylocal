# ReplyLocal 0.2 — первый этап backend

Это полный исходный проект с рабочими аккаунтами, PostgreSQL, настройками компании, базой знаний и приёмом заявок. Презентационный чат вынесен в `/ru/demo` (также `/uk/demo`, `/en/demo`).

**Реальная AI-модель, получение сообщений из мессенджеров и отправка ответов клиентам ещё не подключены.** Этот этап можно использовать для проверки кабинета и подготовки пилота. Он не завершает коммерческий сервис целиком.

## Что работает

- Регистрация создаёт пользователя, отдельную компанию и владельца компании одной транзакцией.
- Вход и выход; сессии в базе, cookie HttpOnly / SameSite=Lax / Secure в production, срок 7 дней. Пароли хешируются scrypt. Смена пароля отзывает все сессии пользователя.
- В кабинете показываются данные своей компании. Сервер проверяет сессию и роль для каждого защищённого API; организация не берётся из тела запроса.
- Услуги, товары, правила и FAQ: добавление, редактирование, удаление, поиск. Данные сохраняются в PostgreSQL. Цена 0 и отсутствие цены различаются.
- Профиль компании и инструкции будущему AI сохраняются. Версия записи защищает от перезаписи параллельного изменения.
- Заявка с лендинга сохраняется только после согласия. Есть выгрузка заявок в CSV для владельца проекта.
- RU / UK / EN, мобильный кабинет, обработка ошибок. Заглушки интеграций больше не сообщают об успешном подключении.

## Быстрый запуск на компьютере

Понадобятся Node.js 22 или новее, npm и **пустая отдельная PostgreSQL-база**. Локальную БД устанавливать необязательно: можно использовать выделенную тестовую базу у своего провайдера. Рабочие данные не хранятся в файловой системе Vercel.

1. Распакуйте архив и откройте терминал в папке `replylocal`, где находится `package.json`.
2. Установите зависимости:

```sh
npm ci
```

3. Скопируйте `.env.example` в `.env.local` через проводник или редактор. Заполните:

```dotenv
DATABASE_URL=postgresql://USER:PASSWORD@HOST:5432/DATABASE
APP_URL=http://localhost:3000
ALLOW_SIGNUP=true
```

`DATABASE_URL` получите у своего провайдера; пример выше не является готовыми реквизитами. Сохраните TLS-параметры из строки провайдера. Для локальной базы используйте собственные имя, пароль и имя БД. Не добавляйте `NEXT_PUBLIC_` к секретам и не коммитьте `.env.local`.

4. Создайте таблицы и запустите приложение:

```sh
npm run db:migrate
npm run dev
```

5. Откройте `http://localhost:3000/ru/register`, создайте аккаунт. Добавьте запись в базу знаний, обновите страницу и убедитесь, что она осталась.
6. Для закрытого пилота после создания нужных аккаунтов верните `ALLOW_SIGNUP=false` и перезапустите приложение. Вход существующих пользователей продолжит работать.

Адрес в браузере должен совпадать с `APP_URL`: `localhost` и `127.0.0.1` считаются разными адресами. Браузер сам передаёт Origin; вручную добавлять его во фронтенд не нужно.

Лендинг и `/ru/demo` доступны без аккаунта. Для сохранения заявки нужна настроенная база. Демо использует вымышленные данные в памяти браузера; обновление страницы сбрасывает изменения и ничего не отправляет клиентам.

## Перенос в существующий репозиторий

Сначала сохраните текущую версию отдельным коммитом или копией. Архив содержит целый проект, а не только несколько файлов backend. Изменения фронтенда необходимы для работы с API.

- Перенесите исходники и конфигурацию из `replylocal` в корень вашего проекта с заменой одноимённых файлов.
- Сохраните свою папку `.git` и собственные секреты. `node_modules` и `.next` из старой сборки не нужны; зависимости устанавливаются через `npm ci`.
- **Удалите старый `src/middleware.ts`: вместо него теперь `src/proxy.ts`.** Не оставляйте оба файла.
- Список добавленных, изменённых и удалённых файлов относительно присланного архива находится в `CHANGED_FILES.md`.
- Проверьте `git diff`, выполните проверки из `TESTING.md`, затем сделайте коммит и push обычным способом. Публикация из этого архива автоматически не выполнялась.

`postcss.config.mjs` заменён чистой конфигурацией Tailwind. В итоговом архиве нет загрузчика из исходного файла, реальных ключей, зависимостей и результатов сборки.

## Развёртывание на Vercel

1. Выделите PostgreSQL-базу этому проекту. Для runtime используйте поддерживаемое провайдером подключение с пулером для serverless. Пул в коде ограничен 3 соединениями **на экземпляр приложения**, а не на весь deployment.
2. Примените `npm run db:migrate` к целевой базе из доверенного терминала. Команда берёт `DATABASE_URL` из окружения или `.env.local`. Не направляйте её на БД другого проекта. При необходимости используйте прямую строку подключения для миграции согласно требованиям провайдера.
3. В настройках Vercel выберите Next.js и Node.js 22.x или 24.x. Команда сборки — `npm run build`; миграция намеренно не включена в build.
4. Для Production задайте `DATABASE_URL`, `APP_URL=https://ВАШ-ДОМЕН`, `ALLOW_SIGNUP=false`. Для первичной регистрации владельца временно разрешите signup и после создания аккаунта закройте его. На время этого шага ограничьте доступ к пилоту.
5. После изменения переменных выполните новый deployment. Откройте именно домен, указанный в `APP_URL`: другие домены/алиасы смогут показывать страницы, но POST/PATCH/DELETE будут отклоняться проверкой Origin.
6. Preview должен иметь отдельную тестовую БД и свой точный `APP_URL`. Не подключайте публичные preview к production-данным. После смены preview URL обновите значение и пересоберите deployment.
7. Проверьте регистрацию/вход, сохранение записи после перезагрузки, изоляцию второй компании и форму заявки на реальном домене. Настройте резервные копии у провайдера БД.

Сборка проходит без подключения к БД. Это не означает, что база в Vercel настроена: при отсутствии `DATABASE_URL`, миграций или правильного `APP_URL` операции кабинета не заработают.

Официальные инструкции: [переменные окружения Vercel](https://vercel.com/docs/environment-variables/managing-environment-variables), [окружения](https://vercel.com/docs/deployments/environments), [пулы соединений](https://vercel.com/kb/guide/connection-pooling-with-functions).

## Как получить заявки

Заявки сохраняются в таблице `leads`. Уведомления на email/Telegram пока не подключены. Из терминала с доступом к нужной БД:

```sh
npm run leads:export -- leads-private.csv
```

Файл создаётся только если такого файла ещё нет. Для повторной выгрузки укажите другое имя. CSV исключены из Git; выгрузка содержит контактные данные, храните её у себя. Публичного API со списком заявок нет.

Периодически запускайте `npm run db:maintenance` в доверенном окружении: он удаляет истёкшие сессии и счётчики ограничений. Заявки и журнал действий эта команда не удаляет. Расписание автоматически не создаётся.

## Что осталось до полноценного продукта

1. Выбрать первый канал и подключить его по официальному API: проверка подписи webhook, привязка к компании, история диалогов и сообщений, защита от дублей, очередь отправки, повторные попытки и статусы доставки.
2. Подключить AI-провайдера на сервере: брать знания только текущей компании, ограничивать расходы, показывать источники, передавать сложные вопросы человеку. Сначала режим черновика с подтверждением оператором.
3. Добавить подтверждение email, восстановление доступа, приглашения команды и управление ролями. Сейчас новый аккаунт становится владельцем собственной компании; интерфейса добавления сотрудников и выбора между организациями нет.
4. Добавить оплату и реальные ограничения тарифов, аналитику по сохранённым событиям, уведомления о заявках, процессы экспорта/удаления данных.
5. Перед платным запуском проверить внешнюю PostgreSQL и Vercel под ожидаемой нагрузкой, мониторинг, восстановление из резервной копии и правила хранения контактов.

Сейчас действуют простые лимиты для пилота: 1 000 записей знаний на компанию; регистрация 5 попыток на email / 30 глобально за 15 минут, вход 10 / 120, заявки 3 / 60, изменения знаний и настроек 300 на компанию. Они общие для экземпляров приложения, поскольку хранятся в БД. Это не полноценная защита от сетевых атак; глобальный лимит может временно затронуть других пользователей.

| `src/app/api/` | HTTP API |

| `scripts/` | Миграция, обслуживание, выгрузка, тестовый сервер |
| `tests/` | Проверки данных и браузерные сценарии |
| `API.md` | Формат запросов и ошибок |
| `TESTING.md` | Что проверено и как повторить |
